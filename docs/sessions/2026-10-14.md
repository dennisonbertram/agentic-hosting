## Changes prepared

- Added `scripts/bootstrap-stack.sh` for a clean Ubuntu 24.04 amd64 host. It fails closed when it finds existing ah state, relevant systemd files, Docker daemon config, named registry resources, or an overlapping ingress range. It pins Go and Nixpacks downloads with SHA-256, checks the Docker apt signing-key fingerprint, pins Docker apt packages and container image digests, and installs gVisor from its signed apt repository.
- The proposed topology preserves the API's loopback bind. Traefik uses the `traefik-public` user-defined bridge and the required container name `paas-traefik`, has no Docker provider or socket, and routes API traffic through an socat relay bound only to the bridge gateway with a `/32` source range for Traefik. Port 8081 is not published.
- The installer generates the master key and bootstrap token in restricted files, keeps the token out of stdout, configures a loopback-only registry, and allows the website container to be skipped.
- Updated `deploy/ah.service` to allow writes to the full Traefik dynamic directory and the dedicated `/var/lib/ah-builds` build root, and to set `StateDirectoryMode=0750`. It starts after and wants the build broker. The `ah-build` group is used by ah and ah-builder; the build root is mode `0710` so workers can traverse but not enumerate sibling build directories. The database/key directory remains private to ah.
- The installer copies `deploy/ah-build-broker.service` and `deploy/ah-build@.service`, enables only the broker, and leaves worker instances to be started with validated IDs by the broker.
- Added `docs/ops/fresh-install.md` with DNS, topology, verification, partial-failure handling, and pin provenance.
