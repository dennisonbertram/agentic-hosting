# 2026-10-20 — issue #164 database connectivity

## Planned

Confirm or refute GitHub issue #164: managed database connection strings use `127.0.0.1`, so a service cannot reach its database. Treat the issue text as a hunch. Report root cause, proposed fix, isolation and docs impact. Only implement a fix if it is small, clear, and tested.

## Done

- Confirmed in code: Create hardcodes `127.0.0.1` in the URL and `host` column; `RunDatabase` publishes `HostIP=127.0.0.1` with empty `NetworkMode`; Create never attaches a tenant or data-plane network. Env injection is pass-through.
- Confirmed a second blocker: `ah-tenant-*` is `Internal=true` and `ICC=false`, so attaching the DB to the tenant bridge still would not allow service-to-database TCP.
- Characterization tests: `TestIssue164_DatabasePublishedOnHostLoopbackOnly`, `TestIssue164_CreateConnectionStringUsesHostLoopbackAndSkipsTenantNetwork` (postgres and redis).
- Report: `docs/investigations/issue-164-database-connectivity.md`. README known-issue note. Learnings entry.
- No production networking change and no merge. The recommended fix (per-database ICC=true internal net + DNS alias, keep host-loopback probes) is not a small patch.

## Left incomplete

- Live Docker/gVisor reproduction (no engine in this environment).
- Implementation of the overlay DNS / attach-on-start path, existing-row rewrite, GC prefix, docs/skill updates after the fix.

## Blockers

None for the investigation. Implementation should not ship a hostname-only change.

## Implementation (same day, PR #167)

### Planned

## Setup scripts, local sandbox and runbooks (branch review/setup)

### Planned

Make the project easy to set up: one-command Linux and macOS setup, a `make sandbox` throwaway local instance, runbooks for setup and operations, script tests. Build on `bootstrap-stack.sh` rather than duplicating it.

### Done

- `scripts/setup-linux.sh`: on a fresh host it delegates to `bootstrap-stack.sh`, then installs `ahc` and checks health. On an existing host it does an idempotent upgrade/repair (permissions, missing `AH_ADMIN_TOKEN`, rebuild ah and ahc, changed units, restart only on change, health). It refuses a partially installed host. Supports `--dry-run` and `--yes`.
- `scripts/setup-macos.sh`: Homebrew prerequisites, a Docker engine (Docker Desktop, OrbStack or Colima), builds `bin/ah` and `bin/ahc`.
- `scripts/sandbox.sh` plus the `make sandbox`, `sandbox-down`, `sandbox-status` and `test-scripts` targets.
- Code: `AH_CONTAINER_RUNTIME` (runsc default; runc only with `--dev`, with a warning banner), `AH_WARM_POOL_ENABLED`, `AH_GC_PRUNE_DOCKER`, and the additive `container_runtime` field in detailed health. Tests for each.
